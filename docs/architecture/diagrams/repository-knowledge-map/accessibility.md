# Rivet 儲存庫知識地圖：文字替代內容

這份文字是互動式地圖的完整輔助技術替代內容；`index.html` 以 `aria-describedby` 連結同一份架構敘述。

## 圖的目的

Rivet 的公開讀者與協作代理從同一組文件真相開始：分析、計畫與文件各自承擔不同責任，完成後的持久結論會回寫文件，才開始下一個有界的 BC 切片。

## 閱讀入口與設計原則

- 公開讀者從 `README.md` 了解產品、架構與設計決策。
- 協作代理先讀 `AGENTS.md`，依規範定位文件並處理正式主題。
- `README.md` 指向架構索引；`AGENTS.md` 指向設計原則；設計原則約束架構索引。

## 長期架構真相

- 產品規範保存目標、範圍與成功標準。
- 架構索引保存跨 BC 不變量，並連結 BC 文件與互動式圖。
- BC 文件為每個 Bounded Context 保存唯一的責任、Port 與失敗契約。
- 互動式圖呈現責任邊界與工作流程。
- 文件回寫保存完成後仍成立的結論，避免長期真相只停留在單次主題計畫。

## 正式主題路徑

- 需求釐清界定目標、範圍、非目標與成功標準。
- 技術規格記錄選項、取捨與證據。
- 主題計畫將鎖定決策轉為有 artifact path、步驟與驗收的執行契約。
- 主題驗證執行驗收、圖形驗證與人類審查；通過後回寫文件。
- 若驗證發現範圍改變，流程會進入範圍回退，再回到需求釐清重新分析，而不是即興擴張。

## 工具鏈與下一個切片

- 工具鏈基線保存 Swift、Node、Bun、formatter、lint 與檢查 scripts 的版本基線。
- 完成正式主題後，工具鏈基線支援下一個 BC 切片。
- 下一個 BC 切片會開始新的正式主題，並再次從需求釐清進入同一個流程。

## 視覺語意

- 虛線框代表 Rivet 擁有並可演進的知識契約。
- 實線框代表公開讀者與協作代理等閱讀表面。
- 顏色區分閱讀者與協作代理、入口與設計原則、長期架構真相、正式主題工件，以及工具鏈與未來實作五個責任平面。
